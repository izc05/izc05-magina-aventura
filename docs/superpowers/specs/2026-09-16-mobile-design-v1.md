# Mágina Aventura — Mobile Design V1

## Goal
Turn the approved mobile mockup into the real Expo/React Native app without weakening the existing GPS, offline or route-domain implementation.

## Base
Implementation starts from `feat/integration-gps-visual-v1`. The new work stays isolated on `feat/mobile-design-v1`; `main` is not modified.

## Approved visual direction
The app uses a Sierra Mágina identity: deep forest green, olive green, Sierra gold, warm off-white, white cards and restrained stone-grey text. The official Mágina Aventura mountain/path/sun mark is the canonical brand mark across headers, onboarding, splash and app icon assets.

The main mobile navigation is:

1. Inicio
2. Explorar
3. Mapa
4. Comunidad
5. Perfil

This replaces the older prototype navigation labels (`Rutas`, `Retos`, `Colecciones`, `Ranking`, `Perfil`) as the primary app shell. Progression, challenges, collections and rankings remain product features but live inside their owning screens rather than occupying the main tab bar.

## Screen contract

### Inicio
- Brand header with official mark and notifications action.
- Hero copy: `¿Qué aventura hacemos hoy?`.
- Search entry for routes, places and experiences.
- Four quick actions: Rutas, Mapa, Cerca de ti, Favoritos.
- Real route data only; no invented activity statistics.
- Featured route cards use the existing route fixtures/domain data until Supabase catalog wiring replaces them.

### Explorar
- Search and filter-first layout.
- Route cards show distance, duration, elevation and difficulty from route-domain data.
- Existing route detail navigation is preserved.

### Ficha de ruta
- Existing verified route detail presenter remains the source for display values.
- Hero, facts, map, safety/offline preparation and start-adventure flow keep working.
- Visual treatment follows the approved white-card/green-accent layout.

### Mapa
- Existing MapLibre/offline route map remains the map engine.
- The visual shell uses a dark-green header, floating map controls and a bottom information card.
- No fake satellite imagery or fake live positions are introduced.

### Aventura activa
- Existing GPS activity engine remains authoritative.
- UI may show live values only when they come from activity state; otherwise it must label demo/placeholder states honestly.
- Pause/resume/finish behavior is not changed by the visual work.

### Comunidad
- Existing community feature remains the data source.
- Visual layout uses activity cards, photos, reactions and tabs without fabricated counts in production data.

### Perfil
- Profile owns levels, achievements, collections, favorites and statistics.
- Main navigation therefore does not need separate Retos/Colecciones/Ranking tabs.

## Brand system
- Canonical name: `Mágina Aventura`.
- Descriptor: `SIERRA MÁGINA · JAÉN`.
- Supporting claim: `Más que rutas, vivencias que dejan huella.`
- Official assets already in `apps/mobile/assets/branding/` are the source files.
- Raster app assets continue to be generated by `pnpm brand:assets`.

## Technical constraints
- Expo Router remains the navigation framework.
- Do not replace MapLibre, GPS background tracking, offline packages or Supabase contracts.
- Prefer existing theme tokens and focused reusable components over page-local duplicated styles.
- No new UI dependency is required for V1.
- Keep TypeScript strictness and existing Vitest coverage.
- All visual changes must pass `pnpm typecheck`, `pnpm test`, Expo Android prebuild and Android debug assembly on CI.

## First implementation slice
The first code slice establishes the final app shell and brand contract: navigation labels, official supporting copy, shell routing, header and Inicio screen. Route-detail/map/GPS internals are preserved and then visually aligned in subsequent slices.
